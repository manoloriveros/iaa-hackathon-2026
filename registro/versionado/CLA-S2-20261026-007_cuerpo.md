## Reconstrucción progresiva, sin falsear fechas

Git guarda dos fechas por commit, la de autor y la de commit. `plan --cronologico` agrupa lo pendiente por día de última modificación (hora de Bogotá) y tema: hoy salen 28 commits, del 20 al 26 de octubre. `aplicar_plan.ps1` hace cada commit con la fecha de autor = última modificación del archivo más reciente del grupo y la fecha de commit real, y el mensaje lo declara. Así el historial muestra la progresión real y GitHub enseña las dos fechas. No se propone falsear también la fecha de commit: el remoto no se actualiza desde el 19 de octubre, los recibos y el foro tienen sus horas UTC y una historia fabricada contradiría nuestra propia evidencia en el criterio de confianza. El script crea las etiquetas `parte1-mezcla-por-peligro` sobre `0ade351` y `parte1-entrega-final-S41` sobre el último commit con archivos de la parte 1, ambas con mensaje que dice que se etiquetaron el 26. Las órdenes de Git del script se probaron en un repositorio sintético (rutas con espacios, eñes, `*` y `[`); PowerShell no se pudo probar en la nube, de ahí el paso `-Simular`.

## Regla y vigilancia
